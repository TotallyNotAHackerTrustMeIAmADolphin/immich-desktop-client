# This client never force-deletes

The prior audit found that the old client's bulk "delete all uploads" could force-delete assets it never uploaded, because a duplicate response was wrongly treated as proof of ownership. While resolving deletion safety (wayfinder ticket #6), we considered gating force-delete more carefully instead (e.g. requiring the ownership hint, or a stronger confirmation) but decided the client will never call `DELETE /assets {force:true}` at all, for any asset, under any circumstance — live delete, catch-up delete, and the manual bulk delete are all trash-only. Trash already gives the user a real permanent-delete option inside Immich itself, on assets they can review first, so the client doesn't need to reimplement it — and removing force-delete from the client's vocabulary entirely eliminates the single most catastrophic failure mode outright, rather than just narrowing when it can happen.
